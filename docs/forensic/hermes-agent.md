## 1. Identity & Purpose

Hermes Agent is Nous Research's personal AI agent — "the self-improving AI agent" (`pyproject.toml` description; `README.md`). Claim (verified in code/docs): it is the only agent with a **built-in learning loop** — it writes skills from experience (`skill_manage`), improves them during use, nudges itself to persist knowledge (background review), searches its own past conversations (FTS5 `session_search`), and builds a user model (MEMORY.md/USER.md + optional Honcho plugin) (`README.md` feature table; `website/docs/user-guide/features/skills.md`, `memory.md`).

`AGENTS.md` states the design intent: one agent core serving CLI, a messaging gateway (~20 platforms), a TUI, and an Electron desktop app; extended "primarily through **plugins and skills**, not by growing the core." Two named invariants shape everything: (1) *per-conversation prompt caching is sacred* — the only sanctioned context mutation mid-conversation is compression; (2) *the core is a narrow waist* — new capability arrives as a CLI command + skill, a service-gated tool, or a plugin, almost never as a core tool (`AGENTS.md` "What Hermes Is", "Footprint ladder").

`SOUL.md` is the persona file: a ~1-paragraph directness charter (match reply length to ask weight, no filler, "Agree because it's right, not because the user said it"). It is seeded to `~/.hermes/SOUL.md`, occupies slot #1 of the system prompt, and is user-editable (`website/docs/user-guide/features/personality.md`).

Deployment posture: "runs anywhere, not just your laptop" — six built-in terminal backends (local, Docker, SSH, Modal, Daytona, Vercel Sandbox; `tools/environments/`), serverless persistence on Modal/Daytona, messaging from Telegram while the agent works on a cloud VM (`README.md`).

Naming/positioning checks: the README badge line says "Built by Nous Research"; the project markets Nous Portal as an optional bundled provider, not a requirement — every provider path is bring-your-own-key (`README.md` § Skip the API-key collection; `cli-config.yaml.example` model.provider options). Migration tooling from OpenClaw/Claude Code/Codex/Cursor is built in via the `agent-importers` catalog plugin (`hermes import-agent openclaw --dry-run`; `README.md` § Migrating).

## 2. Architecture

**Layout** (verified against tree; canonical structure documented in `AGENTS.md` § Project Structure):

- Facades + siblings: every former god-file is a facade with `<stem>_<topic>.py` siblings, e.g. `run_agent.py` → `agent/turn_*.py`, `hermes_state.py` → 70+ `hermes_state_*.py` siblings, `cli.py` → `hermes_cli/cli_*_mixin.py`, `gateway/run.py` → `gateway/run_*.py` (`AGENTS.md` § Facade + siblings layout).
- `agent/` — turn loop phases, providers/transports, memory, compression, curator, prompt builder.
- `tools/` — 289 tool modules + `tools/registry.py` (no-dep registry) + `tools/environments/` (terminal backends) + MCP client (`mcp_tool*.py`, ~30 files).
- `gateway/` — messaging gateway (`run.py` facade, `run_*.py` phases, `session*.py`); platform adapters are plugins under `plugins/platforms/` (27 adapters: telegram, discord, slack, signal, whatsapp(x2), email, sms, matrix, mattermost, feishu, dingtalk, wecom, weixin, qqbot, yuanbao, line, irc, ntfy, a2a, google_chat, teams, simplex, photon, raft, buzz, bluebubbles).
- `hermes_cli/` — 647 files: CLI subcommands, config system, plugin loader, updater, profiles, skins.
- `tui_gateway/` + `ui-tui/` — Python JSON-RPC backend + Ink (Node) TUI; the same backend serves Desktop and the web dashboard.
- `acp_adapter/` — Agent Client Protocol server (editor integration).
- `apps/desktop/` — Electron app; `web/` — Vite dashboard SPA embedding the real TUI.
- `plugins/` — in-tree plugin kinds (memory, model-providers ×38, context_engine, image_gen, delegation, platforms, kanban); `plugin-catalog/` — one YAML per out-of-tree plugin, SHA-pinned.
- `skills/` (44 bundled) + `optional-skills/` (149 shipped-not-active); `cron/` scheduler; `evals/`, `batch_runner.py`, `trajectory_compressor.py` (research tooling).
- `pm/` — "PM", a bespoke dependency/environment manager (own AGENTS.md, `uv.lock` owned by `hermes pm lock`).
- `hermes_platform/` — machine facts + executable lookup (one resolver for host capabilities, `hermes_platform/AGENTS.md`).
- Cross-cutting top-level modules: `hermes_constants.py` (`get_hermes_home()`/`display_hermes_home()` — the profile-aware path seam, lint rule HX001), `hermes_logging.py`, `hermes_yaml.py`, `utils.py` (atomic JSON/YAML writers).

**Entry points:** `hermes` → `hermes_cli.main:main` (REPL + all subcommands); `hermes --tui` → Ink UI; `hermes gateway start/run` → messaging gateway; `hermes-acp` → `acp_adapter.entry:main`; `run_agent.py` importable as library (`AIAgent`); `python -m acp_adapter`. `hermes serve` runs the Desktop control-plane backend. Library embedding is first-class: `AIAgent(base_url=..., model=...)` in three lines (`run_agent.py` docstring).

**Data flow (text diagram):**

```
 User surfaces                     Session authority              Agent core
 ─────────────                     ─────────────────              ──────────
 CLI (cli.py REPL)  ─┐
 TUI (Ink) ══ JSON-RPC ══ tui_gateway/server.py ─┐
 Desktop (Electron) ══ WS ══ (same backend)      │   /api/ws admissions
 Dashboard (web/) ══ WS ══ (same backend)        ├──────────────┐      ┌──────────────────────┐

 Messaging: gateway/run.py → plugins/platforms/* adapters ──→ gateway session lanes       │

                                                                 │                        │
                                    run_conversation (agent/conversation_loop.py)          │
                                        │ preflight → request assembly → API call          │
                                        │            agent/transports/* (per API mode)     │
                                        │ tool_calls → tools/registry.handle_function_call │
                                        │            (INLINE_TOOL_EXECUTORS intercept first)│
                                        ▼                                                  │
                              SQLite state.db (hermes_state*.py) ←— session persistence ───┘
                                        └→ background review fork (agent/background_review.py)
                                           → MEMORY.md/USER.md + skill_manage writes
                                           → curator (agent/curator.py) maintains skills
```

**Runtime processes:** a typical install runs at most two long-lived processes — the CLI/TUI session (or Desktop-spawned `hermes serve` backend) and the messaging gateway (`gateway run`); they communicate through the session-authority WebSocket, not shared memory. One gateway process can serve many named profiles (`gateway.multiplex_profiles`, default-on when ≥2 profiles exist; `hermes_cli/AGENTS.md` § Profiles). Agents are cached per session lane with TTL/LRU/memory-pressure eviction (`gateway/run_agent_cache.py`), and eviction runs inside the owning profile's scope so `on_session_end` memory flushes hit the right store (`gateway/AGENTS.md` § Profile scope).

## 3. Agent Loop

- **Facade:** `run_agent.py::AIAgent` (~60 constructor params: provider, model, `api_mode`, toolsets, platform, session, budget, credential pool) assembled from mixins (`agent/turn_facade.py`, `client_lifecycle.py`, `stream_delivery.py`, `session_persistence.py`, `compression_facade.py`). `chat(message)->str` is the simple API; `run_conversation(...)->dict` returns `final_response` + `messages` (`agent/AGENTS.md`). A turn begins by taking a session turn lease (`agent/turn_facade_lease.py`), which serializes concurrent turns on one session.
- **Loop:** `agent/conversation_loop.py::run_conversation` — entirely **synchronous** while-loop over `max_iterations` (default 500, shared with subagents) and an iteration budget with a one-turn grace call (`agent/iteration_budget.py`); interrupt checks between phases (`agent/interrupt_control.py`, `turn_liveness.py`). Each phase is a sibling file: `turn_preflight_gate.py` (pre-LLM gate incl. preflight compression), `turn_iteration_prep.py`, `turn_request_assembly.py`/`turn_api_request.py`, `turn_api_call.py` (with `nous_rate_limit_guard`), `turn_api_error.py`, `turn_response_intake.py`/`turn_response_check.py`, `turn_empty_response.py`, `turn_tool_round.py`/`turn_tool_validation.py`, `turn_overflow.py`, `turn_truncation.py`, `turn_scripted_prelude.py` (tool calls a prompt built-in plays before the first model call), `turn_context_compaction.py`, `turn_recovery.py` + `turn_recovery_autorecover.py` (post-exhaustion wait-and-retry ladder), `turn_retry_state.py`, `turn_stop_gates.py`, `turn_final_response.py`, `turn_finalizer.py`, `turn_summary.py` (`agent/AGENTS.md` § Agent loop; verified in tree).
- **Prompt assembly:** `agent/system_prompt.py::build_system_prompt` joins three tiers — `stable` (identity/SOUL.md, guidance, env hints, coding brief, platform hints), `context` (workspace snapshot, caller system_message, context files from CWD only, capped by `CONTEXT_FILE_MAX_CHARS` / dynamic cap / `context_file_max_chars`), `volatile` (skills index, memory, USER.md, external provider block, timestamp line) — built once per session, rebuilt only by compression (`agent/system_prompt.py` header; `agent/prompt_builder.py`; `agent/AGENTS.md` § Message-flow invariants). Subdirectory `AGENTS.md` hints are appended to tool results, head+tail truncated past 32k chars (`agent/subdirectory_hints.py`), and install-tree AGENTS.md files are never loaded as project context.
- **Prompt caching:** `agent/prompt_caching.py` builds a per-provider cache plan (e.g. Anthropic `cache_control` placement, TTL handling); cache-break events are recorded as observability metrics (`hermes_cli/observability/shared_metrics_efficiency.py::record_cache_break`, imported by `conversation_loop.py`).
- **Tool dispatch:** model tool calls go to `model_tools.py::handle_function_call`; *agent-level* tools (`todo_list`, `memory`) are intercepted first by the `INLINE_TOOL_EXECUTORS` table in `agent/inline_tool_executors.py` via `agent/tool_executor.py` (no `if name==...` chains). Handlers return JSON strings; the one exception is a multimodal envelope `{"_multimodal": True, ...}` for tools that hand the model pixels (`tools/AGENTS.md`, `tools/registry.py::_normalize_handler_result`). Dynamic schema overrides let a tool reshape its schema per session state (e.g. discord actions by detected bot capabilities, `tools/discord_tool.py`). Tool deferral (deferred tools like `browser_vault`) is handled via `tools/tool_search.py` (`tools.tool_search.defer`).
- **Message format:** OpenAI style (`{"role": system|user|assistant|tool}`); reasoning stored in `assistant_msg["reasoning"]`. Two invariants: strict role alternation (one legal exception: `/steer` as a standalone user row after a tool result) and a byte-stable system prompt for the life of a conversation (`agent/AGENTS.md` § Message-flow invariants).
- **Streaming:** core prefers streaming for every turn including subagents (`cli-config.yaml.example` model.stream); stream monitors (`agent/chat_completion_stream_monitor.py`, `stream_single_writer.py`, `stream_max_lifetime.py`, `auxiliary_stream_watchdog.py`); a stream-delivery layer fans text to the active surface (`agent/stream_delivery.py`); non-streaming fallback exists (`agent/chat_completion_nonstream.py`). Gateway "stream-is-the-message" adapters obey a prefix-stable draft-frame contract with four invariants (draft N is prefix of N+1; consumer declares the final; interim sends carry `metadata["_interim_send"]`; reconcile by edit) — each invariant traces to a live duplicate-final incident (`gateway/AGENTS.md` § Streaming delivery contract).
- **Safety nets in-loop:** repetition/runaway detection (`agent/repetition_guard.py`), empty-response guard (`agent/empty_response_guard.py`), bounded response lengths (`agent/bounded_response.py`), output truncation (`agent/turn_truncation.py`), think-tag scrubbing (`agent/think_scrubber.py`), transcript repair (`agent/transcript_repair.py`), stop gates + estop (`agent/turn_stop_gates.py`, `agent/estop.py`).
- **Retries/failover:** error classification (`agent/error_classifier.py::FailoverReason`), provider-proven rate-limit cooldowns (`agent/fallback_cooldown.py`), fallback model chains (`agent/chat_completion_helpers.py`), persistent multi-credential pools with per-model cooldowns (`agent/credential_pool.py`), auto-recovery ladder `agent/turn_recovery_autorecover.py`.
- **Context management:** three-layer compression — gateway session hygiene at 85% threshold, agent `ContextCompressor` at 50% (configurable, per-model overrides), and micro-compaction (`agent/micro_compaction.py`). Algorithm: prune old tool results deterministically → pick boundaries → structured summary via the *auxiliary* compression model → in-place compaction keeping a stable session id. Compression is the single sanctioned cache break (`agent/AGENTS.md` § Compression; `website/docs/developer-guide/context-compression-and-caching.md`).

## 6. Permissions & Safety

- **Stated trust model:** `SECURITY.md` §2 — "The only security boundary against an adversarial LLM is the operating system." Nothing in-process (approval gate, redaction, pattern scanners) is treated as containment; two OS-level postures: terminal-backend isolation (Docker/SSH/Modal/Daytona/Vercel — file tools also run through the backend) and OS sandboxing. This is an unusually honest, load-bearing policy statement.
- **Approval gate:** dangerous-command approval with three guard entry points (`tools/approval.py::check_all_command_guards`, `check_execute_code_guard`, `request_tool_approval`); pattern detection (`tools/approval_detection.py` hardline/dangerous patterns), permanent per-profile allowlists + user deny rules (`tools/approval_floors.py`), per-session YOLO mode (`/yolo`; `approval_yolo.py`), denial breaker (repeated denials short-circuit with an addendum to the prompt), and a **"smart approval" guardian LLM** that pre-screens ambiguous commands (`tools/approval_smart.py`). Gateway approvals round-trip to the chat platform with request ids, settle observers, and withdrawal (`tools/approval_gateway_wait.py`, `approval_human_wait.py`); ACP renders approval prompts natively (`acp_adapter/permissions.py`, `edit_approval.py`); batched terminal approvals exist for CLIs that fire many commands (`agent/terminal_approval_batch.py`).
- **Terminal hardening:** workdir character allowlist, heredoc stripping, supervised-gateway lifecycle blocks, Windows self-repo git guard (`tools/terminal_tool_guards.py`); sudo stdin blocks; background teardown signals parent-first (`tools/process_registry_termination.py`); every child process env built through one seam (`tools/environments/local.py::build_subprocess_env`, profile-aware `served_profile_child_env`).
- **Write gates:** `memory.write_approval` and `skills.write_approval` stage agent writes (incl. background-review writes) under `~/.hermes/pending/` for human approval (`website/docs/user-guide/features/memory.md`, `skills.md`).
- **Secret scoping:** `agent/secret_scope.py::get_secret` fails closed under multiplex; one process serves many profiles and `os.environ` holds only the launch profile's values — a whole class of cross-profile leaks is guarded by lint rules HX001–HX012 (`AGENTS.md`).
- **Plugin isolation:** `plugins.isolation: host` runs user plugins in a separate host process over a framed-JSON wire; every user-code import path routes to the host or refuses (`plugins/AGENTS.md` § Plugin host boundary). Catalog plugins are SHA-pinned; a `removed.yaml` kill list is enforced at install/enable/load (`plugins/AGENTS.md` § Plugin catalog).
- **Egress hygiene:** central redactor `agent/redact.py` (secret/credential shapes) with memory-context scrubbing on all outbound text (`agent/memory_context.py`); MoA adds a PII filter with explicit classes for advisor outputs (`agent/moa_loop.py` header, issue #59959 reference); `hook_output_spill` spills oversized hook output to disk instead of context (`tools/hook_output_spill.py`).
- **Skill security:** advisory linter + AST audit (`tools/skills_ast_audit.py`, `tools/skills_guard.py`), OSV preflight for MCP stdio, webhook payloads restricted to `_HERMES_WEBHOOK_SAFE_TOOLS` (no file/system execution, `toolsets.py`).
- **DM pairing / authz:** gateway authorization mixins, paired-DM-only `/login`, allowlists per platform (`gateway/authz_mixin.py`, `gateway/AGENTS.md`).

## 7. Sessions, State & Memory

- **Storage:** single SQLite DB `~/.hermes/state.db` per profile — session metadata, full message history, model config, FTS5 search index; WAL default with documented DELETE fallback and macOS-floored synchronous levels (`cli-config.yaml.example` database section); compression splits sessions via `parent_session_id` chains; sessions source-tagged (`'cli'`, `'telegram'`, …). Facade `hermes_state.py` + ~70 `hermes_state_*.py` siblings (schema, fts, search, wal, repair, rewind, titles, usage, timeline, todo, media, …). The profile's gateway is the *only writer of canonical sessions*; CLI/TUI/Desktop/ACP/cron are clients over `/api/ws`; out-of-process workers write through `RuntimeSessionStore` RPC, never by opening `state.db` themselves (`hermes_state.py` docstring; `website/docs/developer-guide/session-storage.md`). Session titles are LLM-derived (`agent/title_generator.py` through `hermes_state_titles.py`); checkpoints/rewind supported (`hermes_state_rewind.py`, `tools/checkpoint_manager.py`).
- **Profiles:** isolated islands — `~/.hermes` default, `profiles/<name>/` for named profiles, each with own `state.db`, config, SOUL.md, skills; multiplex gateway serves many profiles from one process with contextvar-bound secret scopes (`hermes_cli/AGENTS.md` § Profiles).
- **Memory system:** `memory` tool edits two curated files: `MEMORY.md` (agent notes) and `USER.md` (user profile). Both enter the system prompt as a **frozen snapshot at session start** — mid-session writes hit disk but never change the prompt (cache intact) (`tools/memory_tool.py` docstring). Recall fencing: `<memory-context>` fences are stripped from all outbound text by `agent/memory_context.py::StreamingContextScrubber` (anti-exfiltration). Memory-provider plugins (honcho etc., now catalog-external) plug via `agent/memory_provider.py` ABC orchestrated by `agent/memory_manager.py` (one external provider at a time; admission gates for stuck backends).
- **Cross-session recall:** `session_search` tool + `hermes_state_fts.py`/`hermes_state_search.py` (FTS5) with LLM summarization of hits (aux model).
- **The learning loop (the headline system):**
  1. **Foreground capture:** system prompt instructs the agent to record non-trivial workflows via `skill_manage` (create/patch/write_file/delete) — triggered by novel multi-step workflows, dead-end recoveries, user corrections (`website/docs/user-guide/features/skills.md` § Agent-Managed Skills). Skills are markdown + frontmatter per the agentskills.io standard, with `references/`, `scripts/`, `templates/`.
  2. **Background review (memory/skill nudges):** after every turn, `agent/background_review.py` may spawn a daemon-thread fork of `AIAgent` that **replays the conversation snapshot** asking "should any skill/memory be saved or updated?"; the fork inherits the parent's runtime so it hits the *same warm prompt-cache prefix*, runs under a dispatch-side tool whitelist, and writes directly to memory + skill stores without touching the main conversation (`agent/background_review.py` docstring; `website/docs/user-guide/features/memory.md`). Frequency knobs: `memory.nudge_interval`, `skills.creation_nudge_interval`; alternate model route via `auxiliary.background_review` (digest mode, loses warm prefix).
  3. **`/learn`:** `agent/learn_prompt.py` builds one prompt turning any source (code dir, doc URL, pasted notes, "what we just did") into a reusable skill authored via `skill_manage`, embedding the HARDLINE authoring standards (≤60-char one-sentence description, section order, no incident narration — "lessons, not logs").
  4. **Usage telemetry:** `tools/skill_usage.py` owns `~/.hermes/skills/.usage.json` (`use_count`, `view_count`, `patch_count`, `last_activity_at`, `state`, `pinned`); `skill_view` bumps view counts.
  5. **Curator (skill lifecycle):** `agent/curator.py` — inactivity-triggered (not cron) background pass: deterministic transitions `active → stale (14d) → archived (30d)` into `~/.hermes/skills/.archive/` (restorable, never deleted), plus an **opt-in LLM consolidation pass** (`curator.consolidate: true`) that forks an agent to patch, merge into umbrella skills, or archive via `skill_manage` (50–100 aux-model calls per sweep); pinned skills and cron-referenced skills exempt; never-used skills get a grace floor; consolidation must treat a skill as a full package (references/templates/scripts re-homed or archived whole); touches only `created_by: "agent"` skills by default; pre-run tar.gz snapshots (`agent/curator_backup.py`) (`skills/AGENTS.md` § Curator; `website/docs/user-guide/features/curator.md`).
  6. **Write gating:** both foreground and background skill/memory writes can be staged for human approval (`skills.write_approval`, `memory.write_approval`) — staged writes survive restarts under `~/.hermes/pending/` and are approved via `/memory pending` / `/memory approve all`.
  7. **"Learning made visible":** `agent/learning_graph.py` assembles a skill+memory graph for Desktop (nodes = learned skills and MEMORY/USER.md chunks; edges from `related_skills` and lexical overlap); `agent/insights.py` powers `/insights [--days N]` usage analytics.

**Cron as memory-safe automation:** cron sessions run with `skip_memory=True` by default — memory providers intentionally never run during cron, so scheduled jobs cannot pollute the user model (`agent/AGENTS.md` § Memory; `cron/AGENTS.md`). Cron job fields include `skills` (pinned skills), `model`/`provider` overrides, `context_from` (chain job A's output into job B), `timezone` pin, and inactivity watchdogs (`cron/jobs.py`, `cron/scheduler.py`).

## 10. Configuration

- **Files:** `~/.hermes/config.yaml` (all behavior; `_config_version: 52` migration counter), `.env` (**secrets only**, enforced policy), profile-scoped copies; managed overlay (`/etc/hermes/config.yaml`-style) beats profile config for operator pins; `cli-config.yaml.example` documents every section (`hermes_cli/AGENTS.md` § Config system).
- **Precedence & loaders:** three loaders — `load_cli_config()` (CLI), `load_config()` (subcommands, merges `DEFAULT_CONFIG`), `load_user_config_effective()` (gateway/TUI/cron: user file + managed overlay + `${VAR}` expansion, no defaults). ## 11. Standout Features

1. **Warm-cache background self-review:** every turn can fork a same-runtime `AIAgent` on a daemon thread that replays the conversation and decides what to save as memory/skill, reusing the parent's prompt-cache prefix — self-improvement at near-zero marginal context cost (`agent/background_review.py`; `website/docs/user-guide/features/memory.md`).
2. **Agent-authored skills as procedural memory:** `skill_manage` (create/patch/write_file/delete) with an advisory linter (description ≤60 chars, incident-log-shape, references-sprawl, oversized-body warnings) — the agent writes its own reusable procedures in a standard format (`tools/skill_manager_tool.py`; `skills/AGENTS.md`).
3. **Curator lifecycle manager:** inactivity-triggered maintenance of agent-created skills — deterministic stale/archive transitions + opt-in LLM consolidation (umbrella merging), archive-never-delete, tar.gz snapshots, cron-reference awareness (`agent/curator.py`, `agent/curator_backup.py`).
4. **`/learn` one-prompt skill authoring:** turns any source (directory, URL, notes, "what we just did") into a standards-compliant skill; no extra engine, works on all backends (`agent/learn_prompt.py`).
5. **Prompt-cache discipline as a first-class invariant:** byte-stable system prompt; memory/skills frozen at session start; mid-turn injections ride user messages/tool results; compression is the single sanctioned cache break; slash commands defer `--now` (`AGENTS.md`; `agent/system_prompt.py`; `tools/memory_tool.py`).
6. **Layered context compression:** deterministic tool-result pruning → boundary selection → aux-model structured summary, at two thresholds (gateway 85% / agent 50%), with stall retry ladders and provider-proven overflow cooldowns (`agent/conversation_compression.py`, `context_compressor*.py`, `micro_compaction.py`).
7. **Facade + siblings codebase discipline:** no god files — every turn phase, gateway phase, and state topic is its own ≤2,000-line file behind a facade; per-unit complexity ratchets enforced by `scripts/code_health` (`AGENTS.md` § Facade + siblings).
8. **One-session-many-profiles with fail-closed secret scoping:** `agent/secret_scope.py` contextvars + lint rules (HX*) prevent cross-profile leaks in a process serving many `HERMES_HOME`s (`gateway/AGENTS.md` § Profile scope).
9. **Six terminal backends + serverless persistence:** local, Docker (with egress control), SSH, Modal, Daytona, Vercel Sandbox — plus plugin backends (Singularity); file tools ride the same shell contract so isolation is coherent (`tools/environments/`; `SECURITY.md` §2.2).
10. **Honest security posture:** `SECURITY.md` declares in-process heuristics non-boundaries; OS-level isolation is the only boundary; guardian-LLM "smart approval", permanent allowlists, denial breakers, staged write approvals (`tools/approval*.py`; `SECURITY.md`).
11. **`execute_code` zero-context-cost pipelines:** the agent writes Python that calls tools via RPC over Jupyter kernels — collapsing multi-step tool chains into one turn (`tools/code_execution_tool.py`, `tools/code_execution_rpc.py`, `tools/code_kernel.py`).
12. **Delegation with roles and durability semantics:** `delegate_task` single/batch subagents, leaf vs orchestrator roles, spawn-depth caps, completion *units* with groups, process/kernel handoff to parents, stop fan-out rules, heartbeat events on long spawns (`tools/delegate_tool.py` + 11 siblings; `tools/AGENTS.md` § Delegation).
13. **Canonical gateway session authority:** one SQLite store, one writer (the gateway); TUI/Desktop/dashboard/ACP/cron are clients over `/api/ws`; identity canonicalization before key derivation; streaming contracts with duplicate-final invariants (`gateway/AGENTS.md`; `website/docs/developer-guide/session-storage.md`).
14. **Typed Python→TypeScript RPC contracts:** TUI JSON-RPC wire declared as Pydantic models in `tui_gateway/contracts/` and generated for TS; unknown params rejected at dispatch; reconnection replays open server→client requests (`tui_gateway/AGENTS.md`).
15. **Supply-chain paranoia:** exact-pinned deps (post "Mini Shai-Hulud" policy, rationale in `pyproject.toml` comments), SHA-pinned plugin catalog with a kill list, OSV preflight on MCP stdio spawns, plugin host-process isolation (`pyproject.toml`; `plugins/AGENTS.md`; `tools/mcp_tool.py`).
16. **Research tooling in-tree:** batch trajectory generation with checkpoint/resume (`batch_runner.py`), trajectory compression to token budgets for distillation training (`trajectory_compressor.py` — protect head + last N turns, summarize only the middle, never split a tool pair), MoA advisor loops (`agent/moa_loop.py`), scenario evals (`evals/`).
17. **Kanban multi-agent work queue:** dispatcher-spawned workers coordinate through `kanban_*` tools with run-ownership CAS, first-class review states, heartbeats, and orchestrator fan-out — a structured alternative to free-form subagent chatter (`tools/kanban_tools.py`; `cron/AGENTS.md`).
18. **Browser runtime with lifecycle reaping:** CDP session resolution chain (operator env → override → cloud provider → real profile → Lightpanda → packaged Chromium), per-cache-key browsers, crash reaper walking every served home (`tools/browser_session.py` chain; `tools/AGENTS.md` § Browser runtime).

## 12. Lessons for Marfim

**Adopt:**

- **Prompt-cache invariants as written law.** Treating "the cached prefix is sacred" as a review-blocking rule (with exactly one sanctioned mutation: compression) keeps cost and latency predictable; Marfim should encode this as a lint/test, not a convention (`AGENTS.md`; `agent/AGENTS.md` § Message-flow invariants).
- **Skills as the primary extension + memory axis.** The SKILL.md progressive-disclosure format (agentskills.io-compatible), injected as a one-line index with on-demand full reads, is cheap, portable, and human-auditable (`skills/AGENTS.md`). Copy the "lessons, not logs" authoring rule and the 60-char description discipline.
- **The full learning loop, not just skill creation.** Capture (foreground + warm-cache background review) → usage telemetry → deterministic prune + opt-in LLM consolidation → archive-never-delete with snapshots. The deterministic/LLM split keeps the always-on part free (`agent/curator.py`; `website/docs/user-guide/features/curator.md`).
- **Facade + sibling refactor discipline.** Splitting turn phases into `turn_*.py` files with ratcheted complexity bounds keeps a huge codebase navigable; Marfim should start with this shape instead of growing into it (`AGENTS.md`).
- **Fail-closed secret scoping for any multi-tenant/multi-profile ambition.** Contextvar-bound scopes + "never read `os.environ` for credentials" + lint rules is the clean solution (`agent/secret_scope.py`).
- **Staged-write approval gates for agent-authored memory/skills** — cheap to implement, big trust win for unattended surfaces (`skills.write_approval` pattern).
- **Registry-based tool discovery** (import-time `register()` + toolset exposure lists) — zero manual wiring, testable contracts ("every registered tool has a toolset") (`tools/registry.py`; `tools/AGENTS.md`).
- **Typed IPC contracts generated from Python.** If Marfim ships a TUI/desktop client, declaring the wire as Pydantic models and generating TS types eliminated a whole drift class for Hermes (`tui_gateway/contracts/`).
- **Single-source registries everywhere.** One `COMMAND_REGISTRY` derives CLI dispatch, gateway dispatch, bot menus, and autocomplete; one `TOOLSETS` dict drives every platform; one identity resolver answers routing per event. Copy the pattern: derive, never duplicate (`hermes_cli/commands.py`; `toolsets.py`; `gateway/session_identity.py`).
- **Cron with agent-grade ergonomics.** Natural-language schedules, per-job model/skill pinning, output chaining (`context_from`), timezone pins, catch-up windows, and inactivity watchdogs make scheduled agents trustworthy (`cron/AGENTS.md`).

**Avoid:**

- **Bespoke dependency/environment management.** `pm/` (custom venv/dependency manager, activation scripts, own lock workflow) is a large maintenance surface and the source of several updater edge cases (top-level `hermes_state_*` sprawl, `_early_recovery.py` repair paths, frozen compat surfaces like `update_handoff.py` that can never be removed). Prefer uv/pip standards.
- **Flat module explosion at repo root.** ~90 `hermes_state_*.py` / top-level `*.py` files rather than packages hurts importability and discoverability; Marfim should package from day one.
- **Numbered incident IDs as prose.** The AGENTS.md files cite internal PR/issue numbers heavily (#85796, #110637, …), which decays for outsiders — cite behavior and tests instead.
- **Process-global mutable state seams** (e.g. `_last_resolved_tool_names` documented as save/restored around subagents) — acknowledged footguns; design them out (`tools/AGENTS.md`; `agent/AGENTS.md`).
- **Same-turn system-prompt mutation entirely** — Hermes' deferral-to-next-session rule exists because even "helpful" mid-session persona changes break caching and replay; adopt the same strictness rather than partial exceptions.
- **God-object constructor injection.** `AIAgent.__init__` taking ~60 parameters is honest but unwieldy; Marfim can group them into a few typed config objects (`agent/AGENTS.md`).
- **Unclear/uncertain areas worth probing before borrowing:** exact behavior of `nous_wire.py`/`relay_*` (Nous-proprietary relay stack), `native/` (empty in this checkout), the `contributors/` tree, and the `hermes claw` legacy command surface — thin documentation, likely fast-moving. The test suite (7,565 files, ~472k LOC) is larger than many products; assume expensive CI if adopted wholesale.
